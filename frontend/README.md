# ETF Theme Radar 前端

研究工作台采用“左侧任务账本 + 右侧工作区”，区分需要处理、正在运行、等待中和历史任务；活动任务通过 SSE 展示持久化证据进度，并区分“新增入库”与“主题有效”。报告详情先展示证据约束的研究结论，再展示执行摘要；支持与反方证据均优先使用中文结构化字段，不展示内部 Evidence ID 或完整 URL。ETF 现状位于右侧紧凑卡，手动刷新生成独立快照，不改变报告版本。
任务详情 GET 遇到瞬时代理断线会重试一次；持续失败时由工作区展示连接错误，变更状态的请求不会自动重放。
报告证据卡的正文由后端返回一至两句经审计的中文事实概括，优先包含原文明示的时间、作者或机构、领域/地点和主要事件；前端不自行补写未知信息，也不展示摘要生成流程占位句。
右侧新建表单使用图标化研究目标卡、来源 Logo 卡、分段时间选择器和输出类型卡，不使用原生下拉框；关闭或降级的来源卡片由能力接口驱动并保持不可选。

该目录承载基金经理研究平台的 Next.js 前端。当前版本完成统一布局、设计系统、导航、研究工作流与真实 API 页面；`/etf-preview` 读取后端不可变天天基金快照，提供三类基金切换、搜索、排序和手动刷新。研究工作台订阅 SSE 持久快照并常驻展示工具运行、完成与主题证据增量；SSE 失败时回退到有限轮询。

## 统一主题研究界面

- 研究工作台只保留“分析 ETF 格局、跟踪产业动量”这一项核心能力，来源和 30 天、90 天、1 年观察窗口由系统自动编排，输出固定为主题研究。
- 新主题从候选卡片或自定义提案开始，先完成人工主题边界确认；已确认主题从可搜索对话框进入，并沿用该主题唯一的规范报告版本链。
- 待核实报告只提供“确认并发布、要求补充研究、放弃本轮更新”三种动作。补充研究备注必须说明证据缺口及其判断影响，提交后重新进入 FIFO 队列。
- 报告正文依次展示核心结论、选择理由、产业链潜力、增长驱动力、ETF 格局、风险、5–10 年三情景、星级综合判断和详细补证路径。
- 报告版本按钮会读取被冻结的历史正文；时间线和比较视图展示结论、评分、ETF 产品及证据缺口的结构化变化。
- ETF 手动刷新显示天天基金与 yfinance 的来源、字段口径和交叉验证状态，只更新独立行情快照，不改变报告结论或版本。

## 本地运行

```powershell
npm install
npm run dev
```

运行 `npm.cmd run test:e2e` 时，Playwright 会为它启动的 Next 进程设置 `RADAR_E2E=1`，仅关闭该进程的产物目录锁。真实数据页面还需要后端已在 `http://127.0.0.1:8001/health` 就绪；常规 `npm run dev` 和桌面启动器不设置此变量，仍保留目录锁。

浏览器固定访问 `http://127.0.0.1:3000`，后端固定为 `http://127.0.0.1:8001`。构建校验使用 `npm run build`。项目根目录的 Windows 启动器禁止端口漂移，并通过服务契约、Worker 心跳和运行锁避免复用旧版本或启动多个实例。

信息源状态页从 `/api/capabilities` 读取规范化元数据，当前预期覆盖 `7/8`，并明确展示 Google Patents、ETF 官方持仓、Yahoo Finance ETF 公开资讯及等待授权的 S&P DJI。可空 logo 使用文字缩写，不渲染空 `src`。

## 目录说明

- `src/app/`：页面路由与全局样式。
- `src/components/`：可复用业务组件和基础界面组件。
- `src/lib/mock-data.ts`：首阶段演示数据，后续替换为 API 请求。

任何浏览器端代码均不得保存或输出 LLM、搜索服务或数据供应商密钥。
