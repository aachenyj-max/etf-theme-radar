# 阶段 5：导航迁移、兼容关闭与生产验收设计

## 目标

将已完成的个人知识库与主题报告主链作为唯一用户入口，移除会造成资产重复或权限误解的旧界面，并完成五人内部试用的单实例生产配置和可验证恢复流程。

## 信息架构与兼容边界

- 主导航只保留首页、主题雷达、ETF 预览、研究工作台和个人知识库。`/evidence` 不再有页面、网关或导航项；底层 `GET /api/evidence*` 保留，主题详情的治理后时间线与报告中的“打开来源”链接继续工作。
- `/reports` 不再是个人保存资料库。它只显示正式主题报告的只读规范版本链，并链接到主题详情；个人旧保存项通过一次可审计、按用户和旧 ID 幂等的迁移复制为知识库条目。正式 `theme_report` 绝不迁入知识库。
- `/product-studio` 不出现在主导航，旧 URL 显示只读迁移说明且不创建任何任务。

## 全局搜索与权限

`GET /api/search` 提升为 v19 的受权跨域搜索。它仅返回主题、每日简报事件、ETF 预览、当前用户的对话和 `KnowledgePermissions` 已授权的知识条目。知识库 ACL 查询在文本匹配、标题投影、计数、排序和截断之前执行；未授权项目不会以标题、ID、计数、结果位置或预算占用形式出现。搜索不返回专用证据浏览器链接或旧报告库链接。

## 迁移模型

新增仅追加的迁移审计记录，键为 `owner_user_id + legacy_report_id`。迁移服务先确定资产是个人保存项；只复制允许的非正式旧内容，写入固定 `legacy-report` 种类、版本化文本和迁移来源元数据。重复调用返回原条目与原审计记录，不创建第二份文件。正式主题报告仍只经 `theme-report:{theme_id}` 的 `report_versions` 链查看。

## 生产部署

生产 Compose 分为单实例 API、单实例持久 Worker、Next.js 和 Caddy；API 不再在 Web 进程的 lifespan 中启动 Worker。API、Worker、Next.js 和 SQLite 文件只使用一个本地 Docker 卷，不能置于 NFS、SMB 或共享盘。默认只发布 `127.0.0.1:8080`；公开覆盖配置仅开放 Caddy 的 80/443 HTTPS，绝不映射 8001、3000 或数据库端口。账号认证、同源写入校验、HttpOnly 会话 Cookie、Caddy 安全头和审计日志保持开启。

备份使用 SQLite 在线备份加知识文件快照；恢复必须先停止 API/Worker，要求精确 `--confirm-target`，只在独立目录演练并验证清单与哈希后才可用于生产。

## 验证

测试首先覆盖导航关闭、迁移幂等与正式报告排除、ACL 优先搜索、产品工作室只读兼容、Compose 单实例/端口隔离及独立恢复。随后执行并记录并发、429/503、SSE 断线、Worker 重启、SQLite 锁、取消竞态、来源失败、空 ETF 快照和总结重建回归，以及 pytest、lint、E2E 和 production build。
