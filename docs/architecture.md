# 架构说明

系统遵循以下数据流：

```text
确定性 Workflow → 有界研究 Agent → 数据连接器/搜索/浏览器 → 原始证据库 → 标准化事件 → 确定性评分 → 人工复核 → Dashboard
```

每个连接器均为独立适配器，单一来源失败不应中止整个 pipeline。原始记录必须保留来源 URL、内容哈希、抓取时间、访问说明和解析版本，以确保任何研究结论可追溯至许可访问的公开证据。

Workflow 持有阶段、审批、取消、恢复、预算和最终状态；PydanticAI Agent 只在采集阶段选择注册工具、判断证据缺口并提交停止理由。模型不能直接执行 SQL、写文件、修改状态或决定确定性评分。`agent_runs` 保存模型、prompt 哈希、用量和停止原因，`tool_calls` 保存参数/结果摘要、延迟、重试和证据增量。隐藏思维链不持久化；中断后从证据账本和工具摘要开始新的 attempt。

普通主题研究由 SQLite 原子队列限制为一个活动槽和一个等待槽。`awaiting_*` 与 `returned` 属于活动状态；活动项完成、取消、失败、配置阻断或被显式结束后，在同一写事务中提升最早等待项。Worker 仍为单执行槽，不会并行领取两个普通研究任务。

不可变报告与动态 ETF 现状分离：`report_versions` 保存冻结正文、结论、ETF 格局与 claim-evidence 引用；`etf_market_snapshots` 保存独立手动刷新行情。报告详情只在读取边界合并最新快照，刷新不会改写报告资产或内容哈希。

首期实现包含 SEC 适配器和 fixture 适配器。SEC 仅使用公开数据，要求配置联系人型 User-Agent，并执行缓存、重试与限速。OpenAlex/arXiv、USPTO、招聘平台及 ETF sponsor holdings 属于后续连接器，尚未实现完整生产接入。

主题评分由配置与确定性代码共同驱动。只有在至少具备三类独立来源、其中一类为官方来源，且上市公司覆盖满足阈值时，主题才能获得高置信度。社交媒体与 Seeking Alpha 均为可选来源，默认关闭，不能单独支持产品发行结论。
